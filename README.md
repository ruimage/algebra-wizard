# algebra-wizard

Интерактивный мастер решений по алгебре: пошаговая диагностика условия задачи и подбор метода решения — от линейных уравнений до параметров и олимпиадных приёмов.

Основано на алгоритмической карте «Константа Лаб». Оригинальная схема: <https://konstantalab.ru/map>

[![Deploy with Vercel](https://vercel.com/button)](https://vercel.com/new/clone?repository-url=https://github.com/ruimage/algebra-wizard)

## Что это

Одностраничное веб-приложение без браузерных зависимостей: интерфейс, стили, данные и логика встроены в один HTML-файл (`algebra_wizard.html`). Исходная карта хранится отдельно в Mermaid, подготовленный граф — в `map.json`; команда обновления автоматически встраивает тот же JSON в HTML. Для просмотра сайта установка пакетов и сервер не нужны. Мастер задаёт вопросы о задаче, переходит между состояниями алгоритма, показывает преобразования и напоминает о типичных ошибках и проверке корней.

## Возможности

- **Разделы исходной карты** — линейные и квадратные уравнения, высшие степени, системы и векторы, дробно-рациональные уравнения, тригонометрия, модули, корни и радикалы, показательные уравнения, логарифмы, неравенства, параметры, текстовые задачи и другие. Число разделов в интерфейсе берётся из JSON.
- **Точная структура карты** — каждый исходный узел и каждый направленный переход, включая подписи, пунктирные связи, циклы и межраздельные переходы. Узлы не объединяются, промежуточные шаги не пропускаются. Актуальные размеры графа выводятся командами проверки.
- **Пошаговая диагностика** — мастер показывает каждый исходящий переход текущего узла; обычные и пунктирные стрелки различаются подписью и оформлением. Конечные узлы не получают автоматического продолжения.
- **Маршрут решения** — сводка пройденных шагов с копированием в буфер и выгрузкой в `.txt`.
- **История пройденных развилок** — быстрый возврат к любому этапу.
- **Тёмная и светлая темы** — выбор запоминается в браузере.
- **Горячие клавиши** — `1`–`9` выбор варианта ответа, `Backspace` шаг назад, `Esc` закрыть меню разделов.
- **Работает без интернета** — после открытия страницы сервер не нужен; нет внешних скриптов, шрифтов и трекеров.
- Адаптивная вёрстка для телефона и десктопа.

Мастер выбирает алгоритм, но не вычисляет корни автоматически: если преобразование меняет область допустимых значений, в конце нужна проверка по исходному условию.

## Структура проекта

```text
algebra-wizard/
├── algebra_wizard.html  # всё приложение: разметка, стили, встроенный граф, логика

├── map.schema.json      # JSON Schema для проверки формы данных
├── package.json         # команды импорта и проверки, зависимости только для разработки
├── package-lock.json    # зафиксированные зависимости
├── docs/
│   ├── map-source.mmd   # сохранённый Mermaid-источник
│   └── map-audit.md     # результаты сверки и примеры исправлений
├── scripts/map.mjs      # CLI: обновление из файла/сайта и сверка JSON/HTML
├── scripts/mermaid-map.mjs # официальный парсер Mermaid и проверки графа
├── tests/               # проверки импорта, JSON, всех переходов и навигации
├── .github/workflows/update-map.yml # проверка по расписанию и обновление карты
├── vercel.json          # конфигурация деплоя на Vercel
├── LICENSE              # MIT
└── README.md
```

## Запуск локально

Файл самодостаточен — просто откройте `algebra_wizard.html` в браузере двойным щелчком.

Если удобнее через локальный сервер:

```bash
npx serve . -l 8000
# или
python -m http.server 8000
```

Затем откройте <http://localhost:8000/algebra_wizard.html>.

## Деплой на Vercel

Проект статический: для публикации подготовленного HTML не нужны сборка и переменные окружения. Зависимости разработчика используются только при обновлении и проверке карты. В `vercel.json` задан Framework Preset «Other» (`"framework": null`) и rewrite корневого адреса `/` на `algebra_wizard.html`, поэтому приложение открывается сразу по корню сайта.

**Вариант 1 — через Git (рекомендуется):**

1. Сделайте форк или используйте кнопку **Deploy** вверху.
2. Зайдите на [vercel.com/new](https://vercel.com/new) и импортируйте репозиторий.
3. Настройки импорта: Framework Preset — `Other`; Build Command — оставьте пустой (сборка не нужна); Output Directory — корень репозитория (`.`). Rewrite корневого адреса задаёт `vercel.json`.
4. Нажмите **Deploy** — при каждом push в основную ветку обновления будут публиковаться автоматически.

**Вариант 2 — через CLI:**

```bash
npm i -g vercel
vercel          # превью-деплой
vercel --prod   # продакшен
```

Приложение также доступно по прямому адресу `/algebra_wizard.html`.

## Автоматическое обновление карты

Workflow `.github/workflows/update-map.yml` запускается каждые 6 часов,
в **03:17, 09:17, 15:17 и 21:17 по Минску** (`17 */6 * * *`, UTC).
Также доступен ручной запуск через GitHub → Actions → Check and update Mermaid map → Run workflow.
Расписание работает после публикации workflow в основной ветке; GitHub может задерживать scheduled-запуски.

На push и pull request запускается проверка сохранённой карты и тестов.
По расписанию или вручную из основной ветки workflow:

1. Проверяет текущую версию проекта.
2. Получает Mermaid-источник с `https://konstantalab.ru/map`, обновляет JSON и HTML.
3. Проверяет граф, соответствие источнику и все обработчики переходов.
4. При изменениях создаёт коммит от `github-actions[bot]` и отправляет его в основную ветку.
   В коммит входят только `docs/map-source.mmd`, `map.json`, `map.schema.json`, `algebra_wizard.html`.
5. Существующая интеграция Vercel с GitHub запускает деплой по этому push.
   Workflow до 10 минут ожидает успешный статус **Vercel именно для проверенного коммита**.
   Ошибка деплоя или отсутствие подтверждения завершает workflow с ошибкой.

Если источник не изменился, новый коммит и новый деплой не создаются; проверяется статус
текущего коммита. Повторный запуск после неуспешного деплоя не выдаёт ложный успех.
Фиксированное количество узлов/стрелок не ограничивает обновление: тесты сверяют размеры
с актуальным Mermaid и JSON. Изменения, несовместимые с поддерживаемым форматом или
контрактами навигации, останавливают автоматическое обновление до записи в GitHub.

Дополнительные секреты Vercel, Deploy Hook и PAT не требуются: используется уже подключённая
Git-интеграция и автоматический `GITHUB_TOKEN` с `contents: write` и `statuses: read`
только в job обновления. Если правила защиты основной ветки запрещают push от Actions,
обновление завершится ошибкой; workflow не обходит защиту и не использует force push.
При параллельном изменении ветки Git отклоняет устаревший push — нужно повторить запуск.

Статус Vercel подтверждает завершение деплоя по данным интеграции. Он не заменяет
проверку отображения сайта в браузере. В публичных репозиториях GitHub отключает
scheduled workflows после 60 дней без активности; при необходимости их нужно включить
повторно в Actions.

## Источник

Проект основан на алгоритмической карте «Константа Лаб» ([konstantalab.ru/map](https://konstantalab.ru/map)) и является её интерактивной реализацией в виде мастера вопросов и ответов.

Карта является основным источником. В `docs/map-source.mmd` сохранены оба исходных Mermaid-фрагмента страницы. Идентификаторы, тексты узлов, разделы, направления, подписи и типы стрелок перенесены без объединения путей. Кнопки разделов, «Назад», «В начало» и «Сбросить» управляют просмотром; они не добавляют стрелок в граф решения. У стрелок без подписи кнопка называет целевой узел.

### Проверка соответствия

Импорт и проверки требуют Node.js 22.13+ и однократной установки зависимостей:

```bash
npm ci
npm run map:check         # проверить Mermaid → map.json → встроенный JSON
npm run map:check:live    # сверить JSON и HTML с текущей картой на сайте
npm run check            # проверить карту и выполнить все тесты
```

Для переноса изменений с сайта: `npm run map:update:live`. Для пересоздания JSON и HTML из сохранённого Mermaid-файла: `npm run map:update`. Для импорта другой версии файла: `npm run map:update -- --source C:/path/to/map.mmd`. Затем выполните `npm run check` и просмотрите diff. Прежние команды `node scripts/map.mjs --live --write` и `node scripts/map.mjs --write` также работают.

### Формат карты и импорт

`map.json` содержит `schemaVersion`, режим `directed`, метаданные источника с SHA-256, разделы, массив `nodes` и массив `edges`. Узел хранит исходный `id`, полный текст в `label` и `data.sectionId`. Стрелка хранит собственный `id`, `sourceId`, `targetId`, подпись `label`, `data.kind` (`solid`/`dotted`) и исходный `data.order`. Стрелки с одинаковыми концами и подписями остаются отдельными записями.

Официальный Mermaid 12.3.0 разбирает синтаксис. Адаптер извлекает `getVertices()`, `getEdges()` и `getSubGraphs()`, нормализует переносы `<br>` и HTML-сущности. Разделы — плоские `subgraph` с названием вида `1. Вход в систему`. Как и в исходной карте, каждый узел явно объявляется отдельной строкой внутри одного раздела; повторные объявления и неявные узлы отклоняются. Принадлежность и порядок узлов определяются местом объявления, поэтому ссылки из других разделов их не перемещают. Первый объявленный узел раздела используется как его вход. Поддержаны направленные обычные и пунктирные стрелки; иные типы, вложенные разделы и неподдерживаемые диаграммы вызывают ошибку вместо потери данных.

`@statelyai/graph` проверяет повторные ID и ссылки на отсутствующие узлы, а также используется для проверки достижимости из входов разделов. Zod проверяет форму JSON и генерирует `map.schema.json`; дополнительно проверяются разделы, их входы и порядок стрелок. Циклы допустимы. Синтаксически корректный Mermaid может не соответствовать исходной карте, поэтому сверка выполняется по полному графу и хешу источника, а не только по количеству узлов.

При ошибке разбора или проверки сохранённые данные не перезаписываются. ID неименованной стрелки вычисляется из концов, подписи, типа и номера одинаковой стрелки, поэтому добавление другой связи не перенумеровывает существующие ID. Явные ID Mermaid сохраняются.

HTML содержит автоматически сгенерированную копию **того же** `map.json`. При загрузке мастер один раз строит индексы узлов и исходящих стрелок за O(V + E). Mermaid, JSDOM, Zod и графовая библиотека в браузер не загружаются.

После замены старого графа ранее сохранённые маршруты версии v1 не восстанавливаются: их узлы и переходы не соответствуют исходной карте. Новые маршруты сохраняются как v2, при восстановлении проверяется существование каждой стрелки.
