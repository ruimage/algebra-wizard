# Сверка с картой «Константа Лаб»

Основной источник: <https://konstantalab.ru/map>, проверено 08.11.2026.
Использованы оба исходных Mermaid-фрагмента `script[data-eq-into="diagram"]`.

## Обнаруженные расхождения

Прежнее приложение содержало 267 самостоятельно описанных состояний и 458
переходов, включая 85 неявных переходов из результатов к `check_start`.
Наличие целевого состояния проверялось, но соответствие исходной карте — нет.
Разбиение состояний отличалось от карты: вопросы и действия объединялись,
отдельные промежуточные узлы отсутствовали, связи меняли назначение.

Примеры восстановленных маршрутов:

- Вход начинается с `Root → QC`, включая корневой объект.
- `LinTarget → LinQ1`, `LinAct1 → LinQ1`, `LinAct2 → LinQ2`:
  сохранены отдельная цель и повторные проверки после действий.
  У `LinAct1` отдельно доступна пунктирная связь с `Hub`.
- `QuadTarget → QuadQ1 → QuadQ2 → QuadQ3`: приведение подобных
  вынесено в исходный отдельный шаг. Случай уничтожения x² ведёт в `Dispatcher`.
- `FracTarget → FracStep1 → FracQ`: цель и фиксация ОДЗ — разные узлы.
  `FracStep1 ⇢ CtrlFrac` доступен отдельно, специальные методы возвращаются
  в `Dispatcher`, а не в добавленный финальный узел.
- `TrigTarget → TrigODZ → TrigQ1`: сохранены все последующие развилки
  и возвраты, включая `TrigQ2`, `TrigQ3`, `TrigQ4`, `TrigQ4b`, `TrigQ5`–`TrigQ7`.
- `WordS4 → WordS5`, `WordS4 ⇢ Dispatcher`, `WordS4 ⇢ SysTarget`:
  три самостоятельных выхода, без слияния шага проверки и выбора решателя.
- `D1 ⇢ CplxEq2`: сохранён условный пунктирный переход к комплексным корням.
- `CtrlSq → CtrlEnd` и остальные проверки ведут в итоговый узел;
  у `CtrlEnd` нет дальнейшей стрелки и нет возврата к контролю.

## Результат

В приложение перенесены 24 раздела, 336 исходных узлов и 531 стрелка.
Каждый исходный ID соответствует одному узлу приложения. Сохранены полные
тексты, разделы, все пары источник–цель, подписи и обычный/пунктирный тип.
Приложение не добавляет переходов между узлами сверх карты.
Расположение блоков на плоскости заменено последовательным просмотром.

Кнопки навигации по разделам и истории позволяют менять точку просмотра,
но не являются переходами графа решения. Варианты исходящих стрелок всегда
показываются раздельно, даже при одинаковой подписи или общей цели.

## Проверки

- `node scripts/map.mjs --live`: официальный парсер Mermaid разбирает живой
  источник; проверенный граф сравнивается с `map.json` и его встроенной
  копией в HTML, а не только по количеству узлов и стрелок.
- `node --test tests/map.test.mjs`: независимая сверка исходных строк узлов
  и стрелок со встроенными данными; выполнение всех 531 обработчиков кнопок
  в изолированном DOM-стенде; проверка 24 входов разделов, конечных узлов,
  циклов, возвратов, смены ветки, маршрута длиной 221 узел, восстановления
  и отклонения повреждённой истории.
- Браузерная проверка: `LinTarget → LinQ1 → LinAct1 ⇢ Hub → B1`,
  отсутствие продолжения у `B1`, восстановление после перезагрузки,
  возврат по истории и отображение сводки. Ошибок и предупреждений
  в консоли браузера не обнаружено. Все 531 обработчик проверены
  автоматически; браузерная проверка охватывает указанный маршрут.

Команда `--live` повторно загружает источник: будущие изменения сайта
должны обнаруживаться как расхождение и переноситься после просмотра diff.

## Подготовка JSON

`npm run map:update` переводит сохранённый Mermaid в `map.json`, генерирует
`map.schema.json` и обновляет встроенные данные HTML. `npm run map:update:live`
загружает исходник с сайта и выполняет тот же процесс. Для произвольного файла:
`npm run map:update -- --source C:/path/to/map.mmd`.

Используются зафиксированные Mermaid 12.3.0, `@statelyai/graph` 2.6.0,
JSDOM 31.0.0 и Zod 4.6.7 только в инструментах разработчика.
Браузер получает подготовленный JSON, разбирает его стандартным JSON.parse
и строит индексы исходящих стрелок. Нужные для импорта API модели Mermaid
изолированы в `scripts/mermaid-map.mjs` и проверяются тестами.

Тесты отдельно проверяют сохранение параллельных одинаковых стрелок,
Unicode, HTML-переносов и сущностей, стабильность ID, отклонение повреждённых
ссылок и недостижимых узлов, неизменность файлов после неуспешного импорта
и запуск мастера в реальном DOM JSDOM. Полная визуальная браузерная проверка
ранее выполнена для маршрута, указанного выше; после смены формата выполнены
DOM-проверка запуска и автоматическое выполнение всех 531 обработчиков.
